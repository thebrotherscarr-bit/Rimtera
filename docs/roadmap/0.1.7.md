### A2 · PE-2: lazy sprite loading and downscaled frames (flagged for the user: master §8.1)
- **Approach:**
  - `SpriteAtlas.Load` builds an index only: name → path, plus the image size from the PNG header. It does no decoding.
  - `Get(name)` decodes on first use into an LRU of decoded bitmaps. Start with a 192 MB budget. Count 4 bytes per pixel, and evict by last use, never during a frame's draw list (pin the current frame's set).
  - Add `Find(name)` (bool, index only). Replace every `_sprites.Get(...) != null`-style existence check in `UI/GraphicalSandbox*.cs`, `UI/ActorAnimator.cs` and `UI/TileArt.cs` with `Find`.
  - Bound `_scaled` with an LRU (64 MB) and clear it on zoom change, as `TileArt.UseSize` does.
  - In `tools/comfy/sprite_post.py`, downscale generated frames to their largest draw size. The rule is the long side ≤ 512 px. Boss frames are 1078×561 today, about 4× too big.
  - Re-run the downscale over the existing `Assets/Sprites/*_{idle,move,attack}_N.png` **before** A3 commits them. Keep the originals out of git, under `art/generated/` as now.
- **Tests (`SpriteMemorySelfTests`):**
  - `Load` decodes nothing (decoded count = 0 after load).
  - `Get` on 50 names keeps the decoded bytes ≤ budget after 5,000 random gets.
  - No `anim_entities` frame is over 512 px on its long side.
- **Measure:** title-screen private memory ≤ 450 MB (now 807 MB in Debug); startup to window ≤ 3.5 s; F10 "actors" < 1 ms in a boss fight.
